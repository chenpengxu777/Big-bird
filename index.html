嵌入式学习笔记

以 STM32 为主线，系统梳理 GPIO 工作模式与通信协议，并扩展定时器/PWM、ADC/DAC、中断/DMA、时钟系统与看门狗。含时序图、寄存器与 HAL 库代码，方便查阅与复习。

一、GPIO 工作模式 GPIO

GPIO（General Purpose Input/Output，通用输入输出）是 MCU 最基础的外设。STM32 的每个引脚可独立配置为 8 种工作模式（4 输入 + 4 输出），由一组寄存器控制。

1.1 GPIO 内部结构

每个引脚内部包含输入、输出两条通路，结构如下（以推挽为例）：

GPIO 内部结构：输入经施密特触发器进 IDR，输出由 ODR 经驱动电路到引脚
  • 输入通路：引脚 → 上/下拉电阻 → 施密特触发器（整形成数字信号）→ 输入数据寄存器 IDR
  • 输出通路：输出数据寄存器 ODR → 输出驱动（推挽/开漏）→ 引脚
  • 模拟输入：旁路施密特触发器，直接连到 ADC，用于采样
  • 复用功能：引脚交给外设（USART/SPI/I2C/TIM），由外设驱动输出或读取输入

1.2 八种工作模式

模式方向电气特性典型用途
浮空输入输入内部无上下拉，悬空时电平不确定外部电路已确定电平的输入
上拉输入输入内部上拉，默认读到高电平按键一端接 GND，按下读到低
下拉输入输入内部下拉，默认读到低电平按键一端接 VCC，按下读到高
模拟输入输入旁路施密特触发器，直连 ADCADC 采样、模拟量测量
推挽输出输出主动输出高/低，驱动强点灯 LED、普通数字输出
开漏输出输出只能拉低，高电平需外部上拉I2C、电平转换、线与
复用推挽输出由外设驱动，推挽特性SPI 的 SCK/MOSI、PWM、USART_TX
复用开漏输出由外设驱动，开漏特性I2C 的 SCL/SDA
记忆口诀输入四种：浮空 / 上拉 / 下拉 / 模拟；输出四种：推挽 / 开漏 / 复用推挽 / 复用开漏。“复用”= 把引脚交给外设控制。

1.3 推挽 vs 开漏（核心区别）

推挽输出 Push-Pull

内部有两个 MOS 管（上管接 VCC、下管接 GND），输出高时上管导通、输出低时下管导通。

  • 能主动输出高和低，带负载能力强
  • 输出电平明确、翻转快
  • 两个推挽输出直接相连会短路，不能线与

开漏输出 Open-Drain

只有一个下管接 GND，无上管。输出高时引脚呈高阻态，须靠外部上拉电阻拉到高电平。

  • 只能主动拉低，不能主动拉高
  • 多个开漏可接一起，实现线与（任一拉低即为低）
  • 改变上拉电压即可电平转换
为什么 I2C 用开漏？I2C 总线上挂多个器件，需要“线与”做仲裁与应答（ACK）；开漏+上拉让任一器件拉低总线都不会烧引脚。同理开漏常用于多器件共享信号线或不同电压域间的通信。

1.4 上拉 / 下拉电阻

上拉（Pull-up）把引脚默认拉高，下拉（Pull-down）默认拉低。作用是避免输入引脚悬空导致电平随机跳变，并给引脚一个确定默认状态。

上拉电阻接 VCC，阻值常见 10kΩ（弱上拉），默认高电平 下拉电阻接 GND，默认低电平 内部 vs 外部STM32 内置约 40kΩ 弱上下拉，由 PUPDR 寄存器配置 选择依据看“无输入时的默认状态”应是什么；按键接 GND 用上拉，接 VCC 用下拉

1.5 施密特触发器

施密特触发器是一种带迟滞（滞回）的比较器，有两个阈值：高阈值 VT+ 和低阈值 VT−。

  • 输入从低升高，超过 VT+ 才判为高；从高降低，低于 VT− 才判为低
  • 迟滞区间内保持原状态，滤除噪声和抖动，把缓变的模拟信号整形成干净的数字方波
  • 数字输入都经过它；模拟输入旁路它以保留真实电压给 ADC

1.6 输出速度与电气参数

输出速度（OSPEEDR）控制输出驱动器的翻转斜率，决定最大切换速率。速度越快边沿越陡，EMI（电磁干扰）也越大。

低速低频信号、普通 IO，功耗与 EMI 低 中速 / 高速SPI 时钟、PWM 等中高频信号 极速最高翻转速率，如高速 SPI/屏幕，注意 EMI 拉电流引脚输出高时能提供的电流（通常 25mA 级） 灌电流引脚输出低时能吸收的电流，通常与拉电流相近
注意直接驱动大电流负载（电机、继电器、大功率 LED）会烧引脚，需加三极管/MOS 管/驱动芯片。一个端口多个引脚的电流总和也有上限。

1.7 复用功能（AF）映射

复用功能让引脚被外设使用。STM32 每个引脚可复用多个外设，用 AFR 寄存器在 AF0~AF15 之间选择。例如 PA9 既可作 GPIO，也可复用为 USART1_TX（AF7）。

常用对照（STM32F4 为例）USART1_TX=PA9、USART1_RX=PA10；SPI1 的 SCK=PA5、MISO=PA6、MOSI=PA7；I2C1 的 SCL=PB6、SDA=PB7。具体引脚与 AF 号需查芯片数据手册的「引脚复用表」。

1.8 相关寄存器详解

寄存器作用说明

二、通信协议总览 COMM

2.1 分类方式

按是否同步

  • 同步：有独立时钟线（SPI、I2C），双方靠时钟对齐
  • 异步：无时钟线（UART、CAN），靠约定速率（波特率）

按传输方向

  • 单工：只发或只收（如收音机）
  • 半双工：可收发但同一时刻只能一方发（I2C、CAN）
  • 全双工：同时收发（SPI、UART）

按数据线数

  • 串行：逐位传输，线少（UART/SPI/I2C/CAN）
  • 并行：多根线同时传多位，快但线多、易串扰

2.2 协议对比

协议线数同步/异步方向速率多节点典型场景
UART2~4异步全双工9600~115200 bps点对点调试、蓝牙/GPS 模块
SPI4同步全双工可达数十 MHz一主多从(片选)Flash、屏幕、高速传感器
I2C2同步半双工100k/400k/1M/3.4M多主多从(寻址)EEPROM、传感器、RTC
CAN2异步半双工最高 1 Mbps多主(按 ID)汽车、工业现场总线
1-Wire1异步半双工较低多从机(ROM 地址)DS18B20 等单总线传感器
RS4852异步半双工最高 ~10 Mbps多节点长距离工业组网、Modbus
选型直觉速度优先选 SPI；引脚紧张选 I2C（2 线多器件）或 1-Wire；长距离/强干扰/多节点选 CAN 或 RS485；最简单点对点调试选 UART。

三、UART / USART COMM

UART（Universal Asynchronous Receiver/Transmitter）是异步串行通信，无时钟线，收发双方需预先约定波特率。USART 在 UART 基础上支持同步模式，实际多当异步串口用。

3.1 帧格式与波特率

一帧由起始位、数据位、校验位、停止位组成，空闲时线路保持高电平。

UART 帧时序：起始位为 1 个低电平 bit，数据位从最低位(LSB)开始发送
波特率 Baud每秒传输的位(bit)数，常见 9600 / 115200；收发双方必须一致 比特率 vs 波特率二进制下二者数值相等；波特率指“符号/秒”，每符号 1 bit 时相同 数据位5~9 位，常见 8 位 停止位1 或 2 位，常见 1 位
常见坑波特率不匹配、TX/RX 接线交叉（A 的 TX 接 B 的 RX）、未共地（GND 必须相连）是串口不通的三大原因。

3.2 校验位原理

校验位用于简单检错：发送方统计数据位中「1」的个数，按约定加一位使总数满足奇偶性；接收方复核。

偶校验数据位 + 校验位中「1」的个数为偶数 奇校验「1」的个数为奇数 无校验不加校验位，最常见
例发送数据 0b10110001（4 个 1）：偶校验加 0（保持偶数），奇校验加 1（凑成 5 个奇数）。奇偶校验只能发现单 bit 错，不能纠错。

3.3 电平标准

标准逻辑电平特点
TTL高≈3.3V/5V，低≈0VMCU 引脚直接输出，仅适合短距离板内
RS232逻辑1 −3V~−15V，逻辑0 +3V~+15V电平反相、电压高，抗干扰强，需 MAX232 等转换芯片
RS485差分 A/B 两线抗共模干扰、多节点、可千米级，半双工
RS422差分 4 线（双差分对）全双工版 RS485，点对多点

3.4 硬件流控

硬件流控用 RTS/CTS 两根线，防止接收方缓冲区溢出：接收方忙时拉低 RTS，通知发送方暂停；发送方看 CTS 决定是否发。多数简单场景用「无流控」（NONE）即可。

3.5 HAL 库示例

C · HAL // 初始化 USART1（PA9=TX, PA10=RX），115200 8N1 UART_HandleTypeDef huart1; huart1.Instance = USART1; huart1.Init.BaudRate = 115200; huart1.Init.WordLength = UART_WORDLENGTH_8B; huart1.Init.StopBits = UART_STOPBITS_1; huart1.Init.Parity = UART_PARITY_NONE; huart1.Init.Mode = UART_MODE_TX_RX; huart1.Init.HwFlowCtl = UART_HWCONTROL_NONE; HAL_UART_Init(&huart1); // 阻塞发送 uint8_t msg[] = "Hello STM32\r\n"; HAL_UART_Transmit(&huart1, msg, sizeof(msg)-1, 1000); // 中断接收（NVIC 需开启 USART1 中断） uint8_t ch; HAL_UART_Receive_IT(&huart1, &ch, 1); void HAL_UART_RxCpltCallback(UART_HandleTypeDef *h){ HAL_UART_Transmit(&huart1, &ch, 1, 1000); // 回显 HAL_UART_Receive_IT(&huart1, &ch, 1); // 再次开启 } // DMA 接收（大批量数据不丢帧） uint8_t buf[256]; HAL_UART_Receive_DMA(&huart1, buf, 256);

四、SPI COMM

SPI（Serial Peripheral Interface）是同步全双工通信，主机提供时钟，速率高、实现简单，但引脚多、无寻址机制（靠片选线选从机）。

SCK

串行时钟，由主机产生

MOSI

主机输出、从机输入（Master Out Slave In）

MISO

主机输入、从机输出（Master In Slave Out）

NSS / CS

片选，低电平选中从机，多从机共享总线

4.1 四种工作模式（CPOL / CPHA）

由 CPOL（时钟空闲电平）和 CPHA（第几个边沿采样）决定，主机与从机必须设同一模式。

模式CPOLCPHA空闲电平采样边沿
Mode 000低上升沿采样
Mode 101低下降沿采样
Mode 210高下降沿采样
Mode 311高上升沿采样
记忆CPOL 决定“闲时高还是低”，CPHA 决定“用哪个边沿”。CPHA=0 在第一个边沿采样，CPHA=1 在第二个边沿采样。多数器件默认 Mode 0。

4.2 多从机连接方式

独立片选（常用）

每个从机一根独立 CS 线，主机分别控制。从机之间 MISO/MOSI/SCK 并联，CS 独立。需要主机有足够的 GPIO 作片选。

菊花链 Daisy Chain

从机串接：主机的 MOSI 接第一个从机，前一个从机的 MISO 接下一个的 MOSI，所有从机共享 CS 和 SCK。省片选线，但数据需逐级移位，延迟大。

4.3 HAL 库示例

C · HAL // SPI1：PA5=SCK, PA6=MISO, PA7=MOSI，主模式、Mode 0 SPI_HandleTypeDef hspi1; hspi1.Instance = SPI1; hspi1.Init.Mode = SPI_MODE_MASTER; hspi1.Init.Direction = SPI_DIRECTION_2LINES; hspi1.Init.DataSize = SPI_DATASIZE_8BIT; hspi1.Init.CLKPolarity = SPI_POLARITY_LOW; // CPOL=0 hspi1.Init.CLKPhase = SPI_PHASE_1EDGE; // CPHA=0 hspi1.Init.NSS = SPI_NSS_SOFT; // 软件片选 hspi1.Init.BaudRatePrescaler = SPI_BAUDRATEPRESCALER_16; hspi1.Init.CRCPolynomial = 7; HAL_SPI_Init(&hspi1); uint8_t tx[2] = {0x00, 0xFF}, rx[2]; HAL_GPIO_WritePin(CS_GPIO, CS_PIN, GPIO_PIN_RESET); HAL_SPI_TransmitReceive(&hspi1, tx, rx, 2, 1000); HAL_GPIO_WritePin(CS_GPIO, CS_PIN, GPIO_PIN_SET);

五、I2C COMM

I2C（Inter-Integrated Circuit）是两线制、半双工、多主多从总线，仅需 SDA（数据）和 SCL（时钟）。两根线都是开漏输出 + 外部上拉。

SDA串行数据线，双向 SCL串行时钟线，由主机驱动 地址7 位地址 + 1 位读写位；也支持 10 位地址

5.1 时序与应答

I2C 时序：SCL 高电平期间 SDA 跳变 = 起始/停止；数据仅在 SCL 低电平期间变化

起始 / 停止条件

  • 起始 START：SCL 高时，SDA 由高 → 低
  • 停止 STOP：SCL 高时，SDA 由低 → 高
  • 数据在 SCL 高电平期间有效，SCL 低电平期间才允许 SDA 变化

应答 ACK / NACK

  • 每传完 8 位，第 9 个时钟由接收方拉低 SDA 表示 ACK
  • 保持高表示 NACK（未应答，常表示结束或无响应）

5.2 完整读写流程

典型「写一个字节到器件内部寄存器」：起始 → 器件地址(写) → ACK → 寄存器地址 → ACK → 数据 → ACK → 停止。读操作需「起始 → 地址(写) → 寄存器地址 → 重新起始 → 地址(读) → 读数据 → NACK → 停止」。

5.3 7 位 / 10 位地址

7 位地址地址段 7 位 + 1 位读写位（R/W），支持 128 个地址，最常用 10 位地址分两段传输，扩展寻址空间，较少用 HAL 库注意7 位地址需左移 1 位传给 HAL 函数（低 1 位为读写位）

5.4 多主机仲裁与时钟拉伸

总线仲裁

多主机同时发数据时，靠线与逐位仲裁：发「1」的主机若检测到总线被拉低，说明有其它主机发了「0」，则自动退出发送。这样地址/数据小的优先，且不损坏总线。

时钟拉伸

从机处理不过来时，可主动把 SCL 拉低，主机检测到 SCL 未释放便等待，实现从机调速。不是所有器件都支持，高速模式下也受限制。

5.5 上拉电阻选择

速度典型上拉电阻
标准模式 100 kbps4.7 kΩ
快速模式 400 kbps2.2 kΩ
快速+ / 高速更小（如 1 kΩ 或主动上拉）
原理电阻太大 → 上升沿变缓、速度受限；电阻太小 → 灌电流过大、功耗高。总线越长、寄生电容越大，需要越小上拉。

5.6 HAL 库示例

C · HAL I2C_HandleTypeDef hi2c1; hi2c1.Instance = I2C1; hi2c1.Init.ClockSpeed = 400000; // 快速模式 400k hi2c1.Init.DutyCycle = I2C_DUTYCYCLE_2; hi2c1.Init.OwnAddress1 = 0; hi2c1.Init.AddressingMode = I2C_ADDRESSINGMODE_7BIT; HAL_I2C_Init(&hi2c1); // 写 1 字节到器件 0x50 的寄存器 0x00 uint8_t reg = 0x00, data = 0x55; HAL_I2C_Mem_Write(&hi2c1, 0x50<<1, reg, I2C_MEMADD_SIZE_8BIT, &data, 1, 1000); // 读回 uint8_t rd; HAL_I2C_Mem_Read(&hi2c1, 0x50<<1, reg, I2C_MEMADD_SIZE_8BIT, &rd, 1, 1000);

六、CAN COMM

CAN（Controller Area Network）是一种差分、多主机、基于消息 ID 仲裁的现场总线，广泛用于汽车与工业控制，抗干扰强、可靠性高。

物理层

  • 两根线 CAN_H 与 CAN_L，差分传输
  • 显性(0)：CAN_H≈3.5V、CAN_L≈1.5V；隐性(1)：两线都≈2.5V
  • 总线两端各接 120Ω 终端电阻，消除反射

特点

  • 无地址，按消息 ID通信（内容寻址）
  • 多主结构，任何节点可主动发送
  • 带 CRC 校验、错误检测与自动重发，可靠性高

6.1 帧结构

段说明
SOF 帧起始1 位显性(0)，表示帧开始
仲裁段ID（11 位标准 / 29 位扩展）+ RTR（远程帧标志）
控制段IDE（扩展标志）+ DLC（数据长度 0~8 字节）
数据段0~8 字节数据
CRC 段15 位 CRC 校验 + 界定符
ACK 段接收节点确认
EOF 帧结束7 位隐性位
帧类型作用
数据帧传输数据（0~8 字节），最常见
远程帧请求其它节点发送数据
错误帧检测到错误时发出
过载帧延迟下一帧传输

6.2 仲裁机制

多个节点同时发送时，靠差分信号的非破坏性仲裁：显性(0)覆盖隐性(1)。发送隐性位却检测到总线为显性的节点，说明有更高优先级的消息（ID 更小），立即退出发送。因此 ID 越小优先级越高，且不会像以太网那样冲突重传。

6.3 位时序与波特率

一个 bit 时间被划分为同步段(SYNC_SEG)、传播段(PROP_SEG)、相位缓冲段 1(BS1)、相位缓冲段 2(BS2)，由预分频 BRP 决定时钟。

公式 波特率 = APB 时钟 / (BRP × (1 + BS1 + BS2)) 例：APB1 = 36MHz，BRP=3，BS1=BS2=5 波特率 = 36M / (4 × 12) = 750 kbps

C · HAL CAN_HandleTypeDef hcan1; hcan1.Instance = CAN1; hcan1.Init.Prescaler = 3; hcan1.Init.Mode = CAN_MODE_NORMAL; hcan1.Init.SyncJumpWidth = CAN_SJW_1TQ; hcan1.Init.TimeSeg1 = CAN_BS1_5TQ; hcan1.Init.TimeSeg2 = CAN_BS2_5TQ; hcan1.Init.TimeTriggeredMode = DISABLE; hcan1.Init.AutoBusOff = ENABLE; hcan1.Init.AutoWakeUp = DISABLE; hcan1.Init.AutoRetransmission = ENABLE; hcan1.Init.ReceiveFifoLocked = DISABLE; hcan1.Init.TransmitFifoPriority = DISABLE; HAL_CAN_Init(&hcan1); // 发送一帧标准帧 CAN_TxHeaderTypeDef txh; txh.StdId = 0x123; txh.ExtId = 0; txh.IDE = CAN_ID_STD; txh.RTR = CAN_RTR_DATA; txh.DLC = 2; uint8_t data[2] = {0xAA, 0xBB}; uint32_t mailbox; HAL_CAN_AddTxMessage(&hcan1, &txh, data, &mailbox);

七、其它协议 COMM

7.1 1-Wire 单总线

1-Wire 只用一根数据线（加地线）完成供电与通信，总线默认被上拉。每个器件有唯一 64 位 ROM 地址，主机先发「寻址命令」匹配目标器件再通信。典型器件：DS18B20 温度传感器。

  • 位时序：靠主机拉低总线的持续时间区分写 0 / 写 1 / 读位
  • 时序要求严格：微妙级延时，需关中断或精确延时，否则读取失败
  • 寄生供电：数据线高电平时给内部电容充电，可省一根电源线

7.2 RS485 / RS422

RS485 用差分信号（A/B 两线）抗共模干扰，支持多节点（可达上百个）、长距离（千米级）。通常配合 Modbus RTU 协议用于工业组网。

RS4852 线半双工，差分，多节点，需方向控制（收/发切换） RS4224 线全双工（两对差分），一主多从 电平差分电压差 > 200mV 判 1 / < −200mV 判 0，抗噪强 转接TTL ↔ RS485 需 MAX485 等收发器芯片

7.3 USB 简介

USB（Universal Serial Bus）是主从式、分层协议的差分串行总线，速率分低速 1.5M / 全速 12M / 高速 480M / 超速 5G 等。STM32 自带 USB 外设可实现 虚拟串口(CDC)、HID（键盘鼠标）等设备，但协议栈复杂，通常用现成库（如 STM32Cube 的 USB 中间件）。

与 UART 区别USB 是同步、差分、主从严格的总线，且带供电（VBUS 5V）；UART 是简单的点对点异步串口。学习顺序建议：先精通 UART/SPI/I2C，再碰 USB。

八、定时器与 PWM TIM

8.1 定时基础

定时器核心是计数寄存器 CNT，在时钟驱动下计数。关键参数：预分频器 PSC（分频）和自动重装载寄存器 ARR（计数上限）。

公式 计数频率 = 定时器时钟 / (PSC + 1) 定时时间 = (ARR + 1) × (PSC + 1) / 定时器时钟 例：定时器时钟 84MHz，PSC=8399，ARR=9999 计数频率 = 84M / 8400 = 10 kHz，定时 1 秒
向上计数CNT 从 0 加到 ARR，溢出触发更新事件（最常用） 向下计数CNT 从 ARR 减到 0 中央对齐先增后减，用于无刷电机等对称波形

8.2 PWM 输出

PWM（Pulse Width Modulation）通过改变占空比控制平均电压/功率，用于 LED 调光、舵机、电机调速。核心是捕获/比较寄存器 CCR：CNT 与 CCR 比较时翻转输出。

PWM 原理：CNT 从 0 计数到 ARR，小于 CCR 输出高、大于 CCR 输出低
公式 PWM 频率 = 定时器时钟 / ((PSC + 1) × (ARR + 1)) 占空比 = CCR / (ARR + 1) × 100% 例：84MHz，PSC=83，ARR=999 → PWM 频率 1 kHz；CCR=500 → 占空比 50%

8.3 输入捕获（Input Capture）

输入捕获在检测到引脚边沿（上升/下降）时，把当前 CNT 值锁存到 CCR。连续两次捕获的差值即为信号的周期/脉宽，用于测量频率、占空比、脉宽。

8.4 输出比较（Output Compare）

输出比较是 CNT 与 CCR 匹配时产生事件（翻转/置位/触发中断），PWM 本质上是输出比较的一种特例（匹配时翻转电平）。

8.5 编码器模式（Encoder）

编码器模式用两个通道的相位差（A 相、B 相正交信号）判断旋转方向并计数，常用于电机测速/测角。A/B 相位领先关系决定正反转，硬件自动增减 CNT。

8.6 HAL 库示例

C · HAL // TIM3 通道 1 输出 PWM（1kHz） TIM_HandleTypeDef htim3; TIM_OC_InitTypeDef sConfigOC = {0}; htim3.Instance = TIM3; htim3.Init.Prescaler = 83; // PSC htim3.Init.CounterMode = TIM_COUNTERMODE_UP; htim3.Init.Period = 999; // ARR → 1kHz htim3.Init.ClockDivision = TIM_CLOCKDIVISION_DIV1; HAL_TIM_PWM_Init(&htim3); sConfigOC.OCMode = TIM_OCMODE_PWM1; sConfigOC.Pulse = 500; // CCR → 50% sConfigOC.OCPolarity = TIM_OCPOLARITY_HIGH; HAL_TIM_PWM_ConfigChannel(&htim3, &sConfigOC, TIM_CHANNEL_1); HAL_TIM_PWM_Start(&htim3, TIM_CHANNEL_1); // 运行时改占空比 __HAL_TIM_SET_COMPARE(&htim3, TIM_CHANNEL_1, 250); // 25% // 定时器中断（1ms 节拍） HAL_TIM_Base_Start_IT(&htim3); void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *h){ if(h->Instance == TIM3){ /* 每 1ms 执行一次 */ } }

九、ADC / DAC ADC

9.1 ADC 基础

ADC（Analog-to-Digital Converter）把模拟电压转为数字量。STM32 常见 12 位 ADC，分辨率 212=4096。

公式 数字量 = 输入电压 / 参考电压 × (2^N - 1) 输入电压 = 数字量 × 参考电压 / (2^N - 1) 例：12 位 ADC，参考 3.3V，读得 2048 → 电压 ≈ 1.65V
分辨率12 位（可配 10/8/6 位），位数越高越精细 参考电压通常为 VREF+，常见 3.3V，决定满量程 采样时间需匹配信号源阻抗；采样越久越稳，转换越慢

9.2 转换模式

单次触发一次转换一次 连续转换完自动开始下一次 扫描多通道依次转换（配合 DMA 搬运结果） 注入/规则规则组常规采样；注入组可插入优先转换（较少用）

9.3 ADC + DMA 连续采样

多通道扫描 + 连续模式 + DMA 循环搬运，是 ADC 采样的标准做法：DMA 把各通道结果自动写入数组，CPU 无需干预，只需读数组即可。

C · HAL // ADC1 单次转换（PA0） HAL_ADC_Start(&hadc1); if(HAL_ADC_PollForConversion(&hadc1, 1000) == HAL_OK){ uint32_t val = HAL_ADC_GetValue(&hadc1); // 0~4095 float volt = val * 3.3f / 4095; } HAL_ADC_Stop(&hadc1); // 连续 + DMA 循环采样（多通道结果写入数组） uint32_t adc_buf[2]; // 2 个通道 HAL_ADC_Start_DMA(&hadc1, adc_buf, 2);
注意ADC 引脚须配模拟输入；可用多次采样取平均 + 软件滤波降噪；参考电压不稳会直接影响精度。

9.4 DAC

DAC（Digital-to-Analog Converter）把数字量转为模拟电压输出，可用于产生任意波形、模拟信号。STM32 DAC 通常 12 位。

C · HAL HAL_DAC_Start(&hdac, DAC_CHANNEL_1); HAL_DAC_SetValue(&hdac, DAC_CHANNEL_1, DAC_ALIGN_12B_R, 2048); // 输出约 1/2 VREF

十、中断与 DMA DMA

10.1 中断与 NVIC 优先级

中断让 CPU 无需轮询，事件发生时硬件自动跳转到中断服务函数 ISR。STM32 由 NVIC（嵌套向量中断控制器）管理。

抢占优先级高抢占级可打断低抢占级的中断，数值越小优先级越高 子优先级抢占级相同时，决定同时挂起的中断谁先执行 中断分组优先级位数在抢占/子优先级间分配（NVIC_PriorityGroup）
中断服务函数原则尽量短、尽快返回；避免在 ISR 里做耗时操作或调用会阻塞的函数；相关标志位需及时清除。

10.2 外部中断 EXTI

EXTI 检测引脚边沿（上升沿/下降沿/双边沿），触发外部中断，常用于按键、传感器信号触发。

C · HAL // EXTI：PC13 下降沿触发（按键按下） void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin){ if(GPIO_Pin == GPIO_PIN_13){ HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_5); // 翻转 LED } } // 需：配置引脚为中断输入、使能 SYSCFG、配置 NVIC 使能 EXTI13

10.3 DMA 详解

DMA（Direct Memory Access）让外设与内存之间直接搬数据，不经过 CPU，大幅降低 CPU 负担，适合 ADC 连续采样、UART 收发大量数据。

传输方向内存→外设 / 外设→内存 / 内存→内存 传输模式单次（传完停止）/ 循环（自动重来，连续采样用） 数据宽度字节 / 半字 / 字 流与通道STM32 每个 DMA 控制器有多个流(Stream)与通道(Channel)，外设映射到固定通道 典型应用ADC 多通道循环搬运、UART+DMA 收发、SPI/DAC 波形生成
中断 vs DMA中断仍需 CPU 执行 ISR 搬数据；DMA 完全由硬件搬运，CPU 只处理完成后的结果。数据量大、速率高时优先 DMA。

十一、时钟系统 RCC SYS

时钟是嵌入式系统的「心跳」，所有外设工作都依赖时钟。RCC（Reset and Clock Control）负责复位与时钟配置。外设使用前必须先使能其时钟，否则无法工作。

时钟源频率说明
HSI16 MHz内部高速 RC，上电默认，精度一般
HSE4~26 MHz外部高速晶振，精度高，经 PLL 倍频
PLL可倍频到主频把 HSI/HSE 倍频得到系统时钟 SYSCLK
LSI32 kHz内部低速 RC，驱动看门狗
LSE32.768 kHz外部低速晶振，驱动 RTC 实时时钟
SYSCLK系统时钟，经 AHB 分频器分给总线（HCLK） APB1 / APB2外设总线，APB1 挂低速外设（UART2/3、I2C、SPI2），APB2 挂高速外设（UART1、SPI1、ADC） 定时器时钟APB 分频为 1 时等于 APB；分频 >1 时为 APB×2（如 F4 的 APB1×2=84MHz）
最常见错误忘了 __HAL_RCC_xxx_CLK_ENABLE() 使能外设时钟，导致外设不工作、寄存器写不进。配置任何外设前先使能其时钟。
C · HAL // 使能各外设时钟（使用前必须） __HAL_RCC_GPIOA_CLK_ENABLE(); // GPIOA __HAL_RCC_USART1_CLK_ENABLE(); // 串口 1 __HAL_RCC_SPI1_CLK_ENABLE(); // SPI1 __HAL_RCC_I2C1_CLK_ENABLE(); // I2C1 __HAL_RCC_TIM3_CLK_ENABLE(); // 定时器 3 __HAL_RCC_ADC1_CLK_ENABLE(); // ADC1

十二、看门狗 SYS

看门狗（Watchdog）是防止程序跑飞/死机的保护机制：程序需在定时器超时前「喂狗」，否则看门狗复位系统，使程序从异常中恢复。

12.1 独立看门狗 IWDG

时钟独立使用内部 LSI（约 32kHz），不受主时钟影响 作用主程序死循环/卡死时复位系统 喂狗在超时前调用 HAL_IWDG_Refresh() 重装计数器
C · HAL hiwdg.Instance = IWDG; hiwdg.Init.Prescaler = IWDG_PRESCALER_64; // 分频 hiwdg.Init.Reload = 4095; // 重装载值 → 超时约 8s HAL_IWDG_Init(&hiwdg); // 主循环里周期性喂狗 HAL_IWDG_Refresh(&hiwdg);

12.2 窗口看门狗 WWDG

窗口看门狗更严格：必须在窗口区间内喂狗，太早或太晚都复位。用于检测程序是否按预期时序运行（而非简单死机）。时钟来自 PCLK 分频。

选择只防死机用 IWDG 即可；需检查程序时序是否异常时用 WWDG。
